# Deploy to Render

## One-click Blueprint deployment

1. Push this repository to GitHub or GitLab.
2. In Render, choose **New → Blueprint** and connect the repository.
3. Render reads `render.yaml` and provisions:
   - one Node web service;
   - one PostgreSQL database;
   - `DATABASE_URL` wired from PostgreSQL;
   - a generated `TOKEN_ENCRYPTION_KEY` used for AES-256-GCM token storage;
   - `/api/health` as the deploy health check.
4. When the deploy turns green, open the service URL and enter a fresh Upstox access token.

No token is required at build time. Never add an Upstox token to Render environment variables: enter it through the application's login page so it is validated and stored encrypted server-side.

## Native Render commands

The Blueprint runs:

- Build: `npm ci && npm run build`
- Start: `npm start -- -H 0.0.0.0 -p $PORT`
- Health: `GET /api/health`

Node is pinned by `.node-version` and `NODE_VERSION` in the Blueprint. `package-lock.json` makes installs reproducible.

## Persistence and schema

The application connects through `DATABASE_URL`. On boot, the existing market engine creates the required tables and indexes idempotently, so a separate migration command is not necessary for a fresh deployment.

## Important runtime notes

- Run **one web instance** with the current in-process REST scheduler. Multiple instances would duplicate provider polling; use a distributed scheduler/lock before scaling horizontally.
- A free Render web service may sleep after inactivity. During sleep, REST polling stops. It resumes when the service wakes, but Delta/CVD starts a new partial-session baseline and is labelled accordingly.
- Free PostgreSQL availability/retention follows Render's current free-tier policy. For a persistent production terminal, use a paid web service and PostgreSQL plan.
- Keep the web service and PostgreSQL in the same region (the Blueprint uses Singapore) to reduce latency.
- Upstox access tokens expire according to Upstox policy and must be re-entered when expired.

## Environment variables

| Variable | Purpose | Default |
|---|---|---|
| `DATABASE_URL` | PostgreSQL connection | injected by Render |
| `TOKEN_ENCRYPTION_KEY` | server-only credential encryption | generated by Render |
| `POLL_QUOTES_MS` | REST quote cadence while open | `10000` |
| `POLL_SCANNER_MS` | scanner/analysis cadence | `12000` |
| `POLL_CHAIN_MS` | option-chain cadence | `20000` |
| `POLL_CLOSED_QUOTES_MS` | quote cadence while closed | `300000` |
| `QUOTE_BATCH_SIZE` | Upstox quote batch size, clamped to 100 | `100` |
| `RATE_LIMIT_RPS` | central token-bucket sustained rate | `25` |
| `RATE_LIMIT_BURST` | token-bucket burst | `25` |

## Verification after deployment

- `/api/health` must return `{ "ok": true }`.
- `/api/health/market-data` reports authentication, universe, polling and quote coverage; it must not say `HEALTHY` until valid fresh quotes exist.
- The System & Audit tab must show `REST_API_POLLING` and provider diagnostics.
- Historical charts work without a token when the public Upstox candle endpoint is available; live scanner/chains/order flow require a valid token.
